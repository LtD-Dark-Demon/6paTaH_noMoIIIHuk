# Отчёт о восстановлении BratanAssistant 3.0

Дата: 2026-10-13

## Основа

Проект восстановлен из `BratanAssistant_full_merged.md` по исходному ТЗ: сохранить существующую архитектуру, восстановить отсутствующее, исправить compile/runtime ошибки, проверить Android 11–14/HyperOS и GitHub Actions, добиться успешной release-сборки.

## Что восстановлено и исправлено

1. Восстановлена структура Android-проекта `com.bratan.assistant`, версия 3.0 (`minSdk 30`, `targetSdk 34`).
2. Добавлен отсутствовавший `AndroidActionExecutor.kt`:
   - строгий белый список действий;
   - фонарик через `TorchController`;
   - Wi-Fi и календарь через пользовательские уведомления/Intent, без незаконного запуска Activity из фона;
   - календарь использует параметр `epoch_ms`, как и системный prompt облачного провайдера.
3. Исправлен XML-ресурс HyperOS: восстановлено экранирование апострофа в `О\'кей`.
4. Исправлена обработка напоминаний: локальный результат больше не блокирует облако, поэтому при наличии API-ключа Claude может извлечь дату/время; без ключа локальное напоминание остаётся рабочим.
5. Исправлена совместимость `ClaudeApiProvider` с ответами, содержащими несколько content-блоков: выбираются блоки `type=text`, а не жёстко `content[0]`. Для короткой классификации thinking отключён в запросе.
6. Добавлены регрессионные unit-тесты для напоминаний и парсинга Claude; для JVM-теста парсера добавлен `org.json` только в `testImplementation`.
7. GitHub Actions теперь запускает unit-тесты, Android Lint и release-сборку, а также выдаёт два артефакта: APK и полный исходный проект с Gradle Wrapper.

## Android / HyperOS

Проверены Manifest и кодовые пути для Android 11–14:
- `RECORD_AUDIO`, `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MICROPHONE`, `WAKE_LOCK`, `RECEIVE_BOOT_COMPLETED` объявлены;
- foreground service помечен типом `microphone`;
- SpeechRecognizer on-device используется только на поддерживаемых API;
- после загрузки/перезапуска предусмотрено восстановление через пользовательское уведомление;
- для Xiaomi/Redmi/POCO есть переходы к Автозапуску и PowerKeeper с fallback на сведения о приложении;
- TFLite лениво загружается, выгружается при нехватке памяти/простое и использует XNNPACK.

## Проверка

CI выполняет:

```bash
./gradlew :app:testReleaseUnitTest :app:lintRelease :app:assembleRelease --no-daemon
```

Отдельно проверяется целостность финальных ZIP/APK после скачивания артефактов.

## Ограничения проверки

В этой сессии нет физического Android/HyperOS-устройства, поэтому фактическое длительное фоновое прослушивание, поведение PowerKeeper и качество SpeechRecognizer должны быть подтверждены установкой финального APK на целевой телефон. Опциональные `mobilebert_quant.tflite`, `vocab.txt`, `intents.txt` в исходном merged-файле отсутствовали и намеренно не выдумывались; без них используются правила и, при заданном ключе, облачный провайдер.
